# Fidelity regression guard

Automated correctness gate for the BetterBuilder candidate. It runs the candidate on the pinned
reference molecules and checks that its conformer ensembles still match the patched-oracle reference
ensembles, within the measured run-to-run noise. Run it after **any** change to the embed before
accepting it — correctness is a gate, not a habit.

## Contents
- `regression_guard.py` — the guard (deterministic: fixed seed + per-conformer RNG).
- `regression_baseline.json` — pinned metrics (per-molecule median NN-RMSD + aggregate).
- `molecules.smi` — the 100 reference molecules (`SMILES name`), self-contained.
- `reference/*.sdf` — the patched-oracle ensembles (200 conformers each, base seed 210185) these
  were validated against. This is the ground truth; regenerated by `build_ligands.local.py`.

## Usage
Run under a Python with RDKit (the patched engine's `oracle_python`); it shells out to the release
`bb-spec` / `bb-embed` binaries (build them first: `cargo build --release` in `rust/`).

```
oracle_python validation/regression_guard.py                    # check → exit 0 PASS / 1 REGRESSION
oracle_python validation/regression_guard.py --update-baseline  # re-pin baseline (after an intended fidelity change)
```

## Gates (from the measured 3-seed noise floor)
FAIL if any of: aggregate median NN-RMSD > 1.32 Å; <2 Å mean < 95%; <1.5 Å mean < 64%;
`≥90%@2Å` count < 85/100; ≥3 molecules worse by > 0.40 Å median NN; any molecule worse by > 0.70 Å.

Unchanged code diffs to zero (deterministic), so it PASSES exactly; only a real fidelity change moves
the metrics. Verified to catch an injected regression (e.g. `BB_GRAD_TOL=5.0 … --allow-env`).

## Re-pinning
Only re-pin (`--update-baseline`) after a **deliberate, validated** fidelity change — never to silence
a regression.
