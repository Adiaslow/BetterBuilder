# Validation

Stages 1 and 3 are gated against Divya's unmodified pipeline, run in her production container, on a
sample of the production workload. The harness, its provenance rules and its current results are in
`parity/` — see `parity/README.md`.

Reference values come only from her code executing: her modules called directly, her functions
extracted and run, or her file traced unmodified. Nothing generated by BetterBuilder, and nothing
generated by a modified copy of the oracle, can serve as reference.

## Corpus

| File | Role |
|---|---|
| `seeds_5000.smi` | systematic 1-in-1800 sample of the 9M production seed file |
| `seeds_5000.provenance` | its source, owner, size, sampling method, date and md5 |
| `seeds_100.smi` | the stage-1 corpus, drawn from `seeds_5000.smi` |

A corpus is characterised before use by how often Divya's amide reweighting fires on it, since that
patch is the only reason her RDKit is not stock: 83% of the production workload, 1.75 patched
torsions per molecule. A corpus without a `.provenance` file beside it is not a corpus.
